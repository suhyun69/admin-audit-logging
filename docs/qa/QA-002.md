# QA-002 — 독립 보안 계약 검증

상태: 부분 구현·부분 검증. 최종 승인 대상이 아니다.
제품 기준점: integration `459c1ab728c3d4b2b21a14b64877bbfc5298afc8`.

서버 계약 테스트는 non-local 프로필의 V1/V2만 사용한다. 독립 Testcontainers DB에만 ADMIN/OPERATOR/VIEWER fixture를 생성하고 매 테스트 초기화한다. 개발용 V3와 Compose DB를 사용하지 않는다. DB 대상 확인 후 reset하며 `MockMvcPrint.NONE`으로 실패 시 인증 쿠키·CSRF·입력 비밀번호가 자동 출력되지 않도록 한다.

7개 서버 검증: 로그인 actor/DB hash·8시간·Secure/HttpOnly/SameSite/Path 쿠키, 잘못된 비밀번호와 원문 비노출·SECURITY 중복 없음, CSRF 누락 및 다른 계정/같은 계정의 다른 세션 혼합 거부, 로그아웃 폐기·쿠키 삭제·기존 토큰 재사용 불가, 만료·비활성·잘못된 토큰, CSRF HttpSession 단독 인증 불가·공개 로그인 CSRF 강제, HTTP actor/correlation/IP/UA/개인정보 정제 및 컨텍스트 정리.

6개 BFF 검증: 위조 Origin/Host/forwarded 차단과 upstream 미도달, 경로·메서드·traversal allowlist, 401/두 Set-Cookie/Retry-After/requestId 전달과 인증 헤더 제한·no-store, 고정 목적지·redirect 추적 금지, 8KiB 수집 요청 제한, timeout/2MiB 응답 제한과 정제된 502. 제품 BFF 코드를 사용하며 HTTP fixture가 인증 기능 자체를 대신 검증했다고 주장하지 않는다.

## 재현 명령

저장소 루트에서 실행한다. Java 21을 `JAVA_HOME`으로 선택하고 Docker가 필요하다. Node는 프로젝트 최소 24 이상을 사용한다.

```bash
cd api
./gradlew test --tests com.example.demo.qa.SessionSecurityContractTest --no-daemon
```

```bash
node --experimental-strip-types --test admin/tests/contracts/bff-security.test.ts
```

두 실행 모두 종료 코드 0. 서버 결과는 `api/build/test-results/test/TEST-com.example.demo.qa.SessionSecurityContractTest.xml`에서 tests=7/failures=0/errors=0/skipped=0으로 확인했다. 초기 sandbox의 localhost listen/connect 거부는 실행 환경 문제였으며 승인된 실행 권한으로 동일 테스트를 다시 수행해 통과했다.

기존 구현 담당 테스트·package/config·티켓 상태는 수정하지 않았다. 선행 통합 이후 최신 integration을 merge하고 위 NOT RUN 시나리오를 추가·실행한 뒤 orchestra에 최종 제출한다.
