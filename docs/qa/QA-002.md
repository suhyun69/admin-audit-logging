## 실제 DB 계약

서버는 non-local V1/V2만 적용한 새 Testcontainers DB를 사용한다. 자체 ADMIN/OPERATOR/VIEWER·회원123 fixture를 만들고 DB 이름 확인 후 해당 테스트 DB만 초기화한다. 개발 V3·Compose DB·기존 구현자 테스트를 변경하지 않았다. `MockMvcPrint.NONE`으로 실패 시 쿠키·CSRF·비밀번호가 자동 출력되지 않게 한다. 테스트 rollback-only 트랜잭션으로 실제 DB 결과를 가리지 않는다.

- AUTH-01~03: 로그인 actor·DB SHA-256만 저장·8시간·Secure/HttpOnly/SameSite/Path cookie, 실패 로그인 원문 비노출·SECURITY 정확히1건, 로그아웃 DB폐기·두 cookie삭제·기존 token재사용401.
- 세션: 만료·비활성·잘못된 cookie는 인증 불가. CSRF HttpSession만으로 인증할 수 없고 공개 로그인도 CSRF가 필요하다. 다른 계정 및 같은 계정의 다른 opaque session 혼합은403이며 세션을 폐기하지 않는다.
- ACL-01: 실제 회원 endpoint에서 ADMIN200→OPERATOR200 양성 대조 후 VIEWER403 ACCESS_DENIED, DB status/version 불변·BUSINESS0·SECURITY/HTTP 각1.
- API-017 회귀: 같은 token으로 실제 no-op PATCH3회 순차·barrier2회 동시 모두200. token/sessionID/updatedAt/version 유지, 인증 HttpSession 미저장·DATA_UPDATE0.
- ACL-02: 실제 전체 감사 endpoint의 ADMIN 양성 조회가 세 actor의 fixture3건을 반환한다. ADMIN actor 필터도 실제1건을 반환한다. VIEWER/OPERATOR 전체 조회403과 본인 /me의 실제1건 반환을 대조하고, 다른 actor 행 비노출을 확인한다. /me의 actorId는 빈 값·다른 ID·본인 ID 모두400이다.
- HTTP·개인정보: server requestId, actor/interaction, remoteAddr·UA512자, query 원문 배제, ThreadLocal/MDC cleanup과 요청당 HTTP·SECURITY 건수를 실제 SQL로 확인한다. token·cookie·비밀번호 원문을 출력하지 않는다.

## BFF와 실제 Next 연동

독립 BFF6은 제품 proxy와 실제 HTTP fixture로 위조 Origin/Host/forwarded upstream미도달, allowlist·traversal·method, 401·분리된 두 Set-Cookie·Retry-After·requestId·no-store, 제한된 credential headers, 고정 목적지·redirect금지, 8KiB요청·timeout·2MiB응답 제한·정제502를 확인했다. 이 fixture가 실제 API 인증을 대신했다고 주장하지 않는다.

별도 실제 Next production stack에서는 익명me401, login CSRF누락403, 잘못된 credential401, 실제 bootstrap/login/me, login후 이전CSRF무효화, logout/쿠키삭제/oldtoken401, 새VIEWER actor전환, 외부Origin403의8항목을 실행했다. 테스트가 생성한 ADMIN/VIEWER 세션은 로그아웃했고 기존 업무 데이터는 변경하지 않았다. 해당 stack은 API-012·017까지의 인증 구현이며 새 API-013 감사 양성 검증은 위 최신 소스의 격리 Spring context에서 수행했다.

## 재현과 근거

Java21과 실행 중인 Docker, Node24 이상이 필요하다. 실행 환경의 Node는26.8.1이었다.

ADMIN_SMOKE_BASE_URL=http://127.0.0.1:13000 node admin/tests/smoke/auth-http.mjs

기존 테스트·제품 코드·package/config·티켓 상태는 수정하지 않았다. QA-004에 보존한 Playwright 의존성과 이 티켓의 실행 조건을 혼동하지 않는다. QA-002 범위의 남은 NOT RUN 항목이나 차단 결함은 없다. 전체 MVP 브라우저 인수는 별도 QA-004의 최종 선행 충족 후 수행한다.
