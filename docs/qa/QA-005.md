## 검증의 독립성과 제한

- 운영 소스·기존 구현자 테스트·마이그레이션·테스트용 제품 endpoint는 수정하지 않았다. QA 소유 fixture와 두 ContractTest·이 보고서만 추가했다.
- 각 테스트의 CLIENT rate window는 전용 test Clock을 단조 증가시켜 분리한다. 25h 이동 뒤에도 시간을 되돌리지 않아 서버 counter를 초기화한 것으로 오인하거나 테스트 간 쿼터를 오염시키지 않는다.
- 요약 snapshot의 Spy는 실제 SQL 결과를 대체하지 않고 첫 실제 집계가 끝난 시점에 별도 실제 DB 커넥션의 커밋만 조율한다. SQL·집계·최근 목록·트랜잭션 격리는 모두 제품 코드를 실행한다.
- DB·필터·페이지는 실제 양성 행 수와 native SQL 순서를 확인한다. 빈 목록에서 actor 검증만 반복해 PASS하지 않는다. 데이터·로그 수는 event/source/request/interaction 조건으로 한정한다.
- 부하 성능·분산 제한·SSE·운영 보존은 이번 범위가 아니다. 브라우저 UI·확인 모달·Explorer 연결과 수집 실패 시 업무 성공은 최종 QA-004의 실제 브라우저 게이트다.

QA-005 범위의 남은 NOT RUN 또는 차단 결함은 없다. 전체 MVP 승인으로 확대 해석하지 않는다.
